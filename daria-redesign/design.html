Structure, navigation and back behaviour

Screen stack

There is one root, the Library, with five lenses. Everything else is pushed on top of it: collection and playlist detail, the add-songs picker, search, song info, the tag editor, and the three Settings screens. Now Playing is an overlay above the stack, not a screen in it, so it can open from anywhere and close back to the same place. Sheets, dialogs and simulated system UI are layers above that.

Entry. Android’s native splash leads into the last-used lens with the last session paused in the dock. First run shows the permission gate instead of the list.

Back, in order. System UI → dialog → sheet → selection mode inside the queue → Now Playing → screen stack → the Songs lens → leave the app (playback continues in the notification). A dirty editor and a non-empty picker selection interrupt Back with a discard dialog whose safe default is “Keep”.

Persistence. Lens, sort, player face, lyrics-face scroll and Settings values persist across launches. Search text does not. The queue, position and timer persist per the contracts; a reboot discards the timer.

Action hierarchy

Each song has exactly one menu, grouped by consequence and identical in every list and in the player:

  • This listening session: Play now · Play next · Add to queue
  • Keep: Add to playlist… (Favourites is the heart in the sheet header and a switch inside Add to playlist)
  • Go to: Album · Artist (· Folder from the player)
  • File: Song info · Share file

Destructive file operations do not exist in Daria; the only file write is Save in the tag editor, which says so before the button is enabled. Playlist and queue removals say “the file stays on your phone” where a person might doubt it.

Feedback. Every reversible action posts a named snackbar with Undo (“Gisooye Baran plays next · Undo”). Irreversible or system-mediated actions (file save, share) use banners and dialogs instead of snackbars.

Dark, RTL, small screen, large text and landscape

Text overflow rule. Titles and artists are single-line with ellipsis at 100–125% text; at 130% and above rows switch to wrapping (two lines maximum for the title, the artist below) so meaning is never hidden. Counts, durations and timer digits use tabular numerals and never truncate. Mixed Persian/Latin metadata uses unicode-bidi: plaintext per field so “Diana Hadad - نیک موزیک” keeps its own direction inside an RTL row. The timeline is always left-to-right: elapsed time on the left, remaining or total on the right, in both locales Contract.

Visual system

Typography

One family, Vazirmatn (SIL OFL), for Latin and Persian, so mixed metadata does not change texture mid-line. Weights 400, 500, 700, 800. Sizes scale with the system font setting; three sizes are capped (wordmark 1.2×, app bar title 1.3×, player title 1.35×) so headers do not consume the screen at 200%.

Colour

Neutral surfaces with a slight blue bias; one accent (lapis) for controls, selection and links; semantic amber for “hidden”, red for errors and destructive confirmations. The player is the one place colour is expressive: its background and transport tint derive from the artwork’s dominant hue (fallback: the neutral tint). Contrast targets: 4.5:1 for text, 3:1 for icons and control edges, in both themes; the tint is mixed with the surface at fixed ratios so artwork can never push text below target. Spacing, density, shape

8-pt rhythm. Rows are 64 px at 100% text with 48 px covers; a 390-px phone shows eight rows above the dock, six with the mini player. Corner radii: 8 rows/covers, 12 fields, 16 mini player, 22 player artwork, 26 sheets and dialogs. Sheets and dialogs are the only elevated surfaces; lists are flat. The dock is a translucent surface with a 1-px top line and a solid fallback.

Icons

Lucide outline icons at 24 px (18 px inside pills and chips), 2-px stroke, filled variants only for play, pause, skip and the favourite heart. Icons never appear without a label except for the standard transport and the ⋮ menu, which carry accessible names.

Artwork behaviour

Embedded art is shown at 48, 56, 120 px and full width. Missing art shows the Daria tile: a generated eight-point-star lattice tinted from a hash of the album name with a small note glyph. It never shows initials or digits. In the player the tile also drives the tint, so a missing-art song still gets a coloured player. Album grids clamp titles to two lines; artists use round tiles.

Component states

Every control has enabled, pressed, focus-visible (3-px accent ring), disabled (42% opacity, never removed) and, where relevant, selected states. Rows add current (accent title + moving bars), hidden (55% opacity + amber badge) and missing (red badge). Fields add changed (accent border + “Changed” label), error (red border + message), normalised (“Will be saved as 1401”).

Blur. The dock uses an 18-px backdrop blur with 86% surface opacity, so text on it always sits on at least 86% solid surface; contrast does not depend on what scrolls beneath. On devices where the design system reports blur as expensive, or when the person enables “Remove animations” in Android, the dock renders solid. Full-surface glass, as in Figma F06/F07, is not used.

Accessibility requirements

Names and reading order

  • Row: one button named “Title, Artist, now playing” + a ⋮ button named “More options: Title”. Duration is part of the row name, not a separate stop.
  • Mini player: “Open player: Title” (full-row button), then Play/Pause, then Next. The timer glyph adds “Sleep timer: 12 minutes” to the artist line’s name.
  • Player: source button, then faces tablist, then face content, then the seek slider (valuetext “0:01 of 3:58”, disabled when duration is unknown), transport, chips. Notices are role=status and precede the faces.
  • Hidden pill: “9 hidden. Why some songs are hidden” so the purpose is announced with the count.
  • Sheets are modal dialogs with the title as the accessible name; focus moves to the title and returns to the trigger.

Targets, gestures, motion

  • Minimum 48×48 dp for every control; 44 dp only inside dense rows of the queue where the row itself is also a target.
  • No gesture-only path: face swipe, sheet drag, player drag-down and queue drag-to-reorder all have tap alternatives (tabs, scrim/Back, chevron, Move up/down in the row menu).
  • Android “Remove animations” is respected for every transition; the timer ring and current-song bars keep information but not motion.
  • Large text: lens row becomes a picker at 130%+; the dock becomes a single row (mini player + search icon) at 130%+ or below 330 px width; wrapping rows replace ellipsis.
  • Colour is never the only signal: hidden and missing rows have badges, changed fields have labels, the current song has bars.

None of this has been checked with TalkBack. It is a specification for the build and a plan item in the validation plan.

Critique through four lenses, and what changed

Product designer

Weakness found: the first version showed the amber “hidden” pill at the shipped 30-second default, which would have told every new user that nine songs were hidden before they touched a setting. Revised: the pill appears only after the person changes a library rule; the default rule is still listed inside the explainer sheet so it is discoverable.

UI/UX designer

Weakness found: the three-face tablist overflowed at 160% text on a 320-px phone, and the wordmark took a third of the header. Revised: labels collapse to icons with accessible names at large text; the wordmark and titles cap their scale. The metadata row stacks vertically in large-text mode.

Product manager

Weakness found: the concept comparison scored Dock highest partly because it is the one with an interactive prototype. Response: the criteria and weights were fixed before scoring, the other two concepts have comparable mockups for the same screens, and the two heaviest criteria (findability, continuity) are argued from tap counts and control positions, not from polish. The bias is acknowledged in the validation plan: Rooms’ resume card and Stage’s persistent player are named as experiments to run.

End user

Weakness found: hiding a folder from its ⋮ menu felt too easy for something that removes 718 songs from view. Revised: the menu row states the count and “Files are not deleted”, the snackbar names the folder and count with Undo, and the Folders lens keeps hidden folders visible with Show. Not revised: no confirmation dialog, because the action is fully reversible in one tap and the contract guarantees nothing is lost.

Final consistency check

  • Every song menu (list, collection, playlist, search, queue, player) uses the same four groups and verbs.
  • Every reversible action has a named snackbar with Undo; every system-mediated one has a banner or dialog.
  • Every gated or empty state has exactly one primary recovery action and, where the contract offers it, one secondary.
  • Every future capability (Settings screens, Lyrics face, lyrics folder, save-queue) is labelled Future or Proposal in this dossier and in the prototype annotations.
  • Persian strings exist for every visible label in the prototype; digits follow the locale except in file names and technical values.

Explanation of the major changes

  1. Search moves from the header to the dock. It is the most general way into a large local library and the current placement is the least reachable one. Nothing about search behaviour changes; it gains typed results and a hidden-folder hint.
  2. The queue becomes a face of the player. The contract’s selection, reorder and Undo semantics get a permanent home that never covers the transport.
  3. One song menu, grouped by consequence. The two shipped menus are merged; verbs are unchanged.
  4. Hidden content is explained where it is felt. New pill, explainer sheet, playlist footer and search hint make the folder invariant visible instead of mysterious.
  5. Settings and Lyrics are designed as future features with immediate, undoable settings and a local-first lyrics scope.
  6. The Daria tile replaces initials and gives every song a colour for the player.
  7. Timer and editor keep their contracts; their presentation is consolidated (one chip, one glyph; changed-field marks, six failure states, correct “playing vs current” copy).
