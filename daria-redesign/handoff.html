Behaviour specifications

Library visibility (Settings, future)

  • Visible(track) = folder shown AND (duration unknown ? keepUnknown : minDuration == Off OR duration ≥ minDuration). Equality is kept.
  • Visibility affects: Songs, Albums, Artists, Folders lists and counts; collection contents; search results; the add-songs picker.
  • Visibility does not affect: files; playlist membership; favourites; play history; the current queue; the current track. Playlists and Favourites show hidden members under an expandable footer with a count; they remain playable (owner decision D7).
  • New folders discovered by the index are shown. Hidden folders are stored by full path + storage identity; a folder that disappears from the index keeps its hidden flag.
  • Album and artist counts are recomputed from visible tracks only.
  • Search over hidden content returns nothing visible, but the results screen shows “n matches are in hidden folders” with a link to Settings › Folders. Minimum-length hidden matches are not counted (they are usually noise).

Queue and playback

  • Play now from a list replaces the queue with that list’s visible items in the current sort and starts at the tapped item; source = list name.
  • Play next inserts after the current occurrence; Add to queue appends. Both post a named snackbar with Undo that removes that occurrence only.
  • Reorder never changes the current occurrence’s identity. Removing items before the current one adjusts the index.
  • Clear queue: confirmation names the consequences (stop, empty, files kept, timer cancelled).
  • Unavailable file: playback stops on that occurrence, error card with “Play next song” and “Remove from queue”; no automatic skip; Share of that file is refused with a message.
  • Unknown duration: no progress bar in the mini player; dashed non-seekable timeline; “Unknown length” label; the end-of-song timer shows no “about n min left”.

Sleep timer presentation

  • Chip states: off (“Sleep timer”), duration (ring + “n min”, updates per minute; per second in the last minute), end of song (“After this song”). Mini-player glyph mirrors the state.
  • +10 refusal: inline amber banner with the reason and a Change time button; the timer is untouched.
  • Change: draft state inside the same sheet; running countdown is shown in text; Keep current timer closes without change; Apply replaces at that moment. If the timer expires while the draft is open, the draft stays, the countdown text becomes “Sleep timer finished”, and only Start arms a new one.
  • Save failure: red banner with Retry saving; Retry persists the current state without touching the deadline.
  • Expiry: quiet pause; “Paused by sleep timer · Stopped at hh:mm” notice in the player and the mini player until dismissed or playback is started deliberately.

Tag editing and sharing

  • Editor opens only for MP3 files that meet the contract (Android 11+, supported tag structure, ≤ 300 MiB). Others show the reason in Song info.
  • Numeric fields normalise Persian/Arabic-Indic digits and preview “Will be saved as …”. Year must be four digits; track must be n or n/m.
  • Empty value removes the tag; unreadable values are left untouched unless replaced (show “unreadable” placeholder).
  • Save sequence: consent (Android) → saving (transport may pause briefly; state announced) → saved-to-file → index-pending banner in Song info until the index reports the new values.
  • Failure states and their single recovery: denied → Try again; externally changed → Reload tags (draft kept); write failed → Restore original + Try again; no space → Try again after freeing; another save in progress → wait indicator.
  • Share hands the actual file to Android’s chooser with temporary read access; feedback for missing file, denied access, no receiving app.

Lyrics (future, first release)

  • Sources: embedded USLT (plain) and SYLT (synced) frames in ID3; a per-song lyrics file (.lrc or .txt) chosen through the system file picker and associated by file identity, stored in app data.
  • Synced: current line follows position; tapping a line seeks. Plain: static text labelled “Not synced to the music”. None: explanation + “Add lyrics file”.
  • Later, separately: a lyrics folder matched by file name (Settings › Lyrics shows the placeholder now); any online provider would need a rights decision and network permission and is not assumed.

Motion budget

See the motion table. Summary: player open 280–360 ms; face switch ≤ 220 ms; tint 400–600 ms; sheets 260–320 ms; nothing loops except the current-row bars. All translations become 120 ms fades under Android’s “Remove animations”.

Content rules

  • Verbs are fixed: Play now · Play next · Add to queue · Add to playlist · Favourite · Song info · Share file · Hide from library · Show in library · Remove from queue · Remove from this playlist.
  • Consequence sentences accompany anything that could be mistaken for deletion: “The songs stay on this phone.” “Files are not deleted.” “The file stays on your phone.”
  • Snackbars name the object: “‘Gisooye Baran’ plays next”, “‘Quick Share’ hidden · 718 songs”. Undo is the only action a snackbar may carry.
  • Counts use tabular numerals and locale digits (Persian digits in Persian). File names, paths, bitrates and codes stay in Latin digits.
  • Titles from file names are marked in Song info (“From the file name — no title tag”), never in list rows by default.
  • Future features are labelled in the product only where the person can act: the Lyrics folder row says “Not connected · later release”. The Lyrics face itself needs no label because its empty state explains the source.
  • Persian copy exists for every visible string in the prototype (see assets/proto.js, object T); it is a first draft for a native reviewer, not final localisation.

Staged rollout

  1. Stage 0 · Foundations (no visible change). Tokens (colour, type scale caps, radii), Daria tile generator with cache, one SongMenuSheet component, snackbar-with-Undo pattern, Persian string review. Risk: low.
  2. Stage 1 · Library and dock. Dock with mini player and search field; lens row with large-text picker; global typed search; authored-first Playlists; sort pill. Keep the existing Now Playing. Risk: medium (new composition; blur fallback). Gate: T1, T2 pass with TalkBack; no list row hidden under the dock at 200% text.
  3. Stage 2 · Player faces. Now Playing with Cover and Up next faces, fixed transport, artwork tint, timer chip, mini-player timer glyph; remove the overflow timer entry. Landscape arrangement. Risk: medium. Gate: T3, T5 pass; queue Undo verified; landscape clipping resolved on the device that reported it.
  4. Stage 3 · Song info and editor presentation. Source sections, non-editable reason, changed-field marks, normalisation preview, six failure states, index-pending banner, corrected playing/current copy. No contract change. Risk: low–medium. Gate: T7 and every failure state exercised on an MP3 test set.
  5. Stage 4 · Settings (future). Folders, minimum length with counts and unknown-length switch, appearance, refresh; hidden pill, explainer sheet, playlist and favourites footers, search hint. Owner decisions D6, D7 required first. Risk: medium (count performance on large libraries). Gate: T6 passes; hiding 718 songs recounts in under 300 ms or falls back to a draft model.
  6. Stage 5 · Lyrics (future). Embedded USLT/SYLT reading, per-song file import, Lyrics face, Song info lyrics row. Owner decision D8 required. Optional later: lyrics folder; online provider only with a rights decision.
  7. Proposals awaiting decision, any stage: Save queue as playlist (D14); Stage mode experiment (validation plan E3).
