Daria Music Player · Product and experience redesign · 28 September 2026

One library, one dock, a player with faces

Concise owner summary of an informed redesign built from the supplied package: the installed app on Hormoz, both prior design rounds and the Figma reference. Three concepts were developed against fixed criteria; Dock is recommended and carried through to an interactive prototype, decision register, coverage ledger, handoff and validation plan.

Deliverables are self-contained HTML; no repository, network service or Figma edit was neededAll interactions are browser simulations; no audio, files or Android services are touched

Decisions worth debating

  1. No Home page and no navigation bar. One library with five lenses; resume lives in the mini player. The Rooms concept is kept in case the owner believes “continue listening” is the dominant job. D2
  2. Hidden songs stay in playlists, favourites and the queue, and can be played from there. The owner invariant requires preservation of files, playlists and the queue; extending it to favourites and history, and allowing playback from the playlist footer, needs a yes. D7
  3. Settings apply immediately with Undo instead of Round 2’s Apply/Discard draft, with the number each option hides shown before choosing. D6
  4. The Lyrics face is visible before lyrics exist, with an honest empty state and a per-song file import as the first release. Alternatively it ships behind a flag. D8
  5. “Save queue as playlist” is offered as a new capability from the queue overflow. It is one menu row to remove. D14

Improvements with the strongest support

  • Search in the dock. The most general way into an 825-song library moves from the least reachable corner to the thumb, on every screen, above the keyboard. Evidence: current placement 01; library size flows.md.
  • Queue as a face of the player. The contract’s selection, reorder and Undo get a home that never covers play/pause. Evidence: sheet over transport 34, Figma F03.
  • One song menu grouped by consequence. Two differently ordered menus become one. Evidence: 28, 37.
  • Hidden content explained where it is felt. Pill, explainer sheet, playlist footer and search hint turn the folder invariant into something visible. Evidence: owner requirement; Round 2 copy.
  • Contracts preserved, presentation consolidated. Timer (one chip, one glyph, every contract state), editor (six failure states, changed-field marks, digit normalisation preview, correct playing/current copy), sharing (actual file). Evidence: 19–33, feature-contracts.md.
  • Every gate and error state designed: first run, denied, blocked, loading, empty, read error, refresh failure, observer unavailable, missing file, unknown duration, all hidden.

Creative bets

  • The dock as a single thumb-reach surface for search and playback, translucent with a solid fallback.
  • Player faces (Cover, Lyrics, Up next) sharing one fixed transport, with the whole player tinted from the artwork.
  • The Daria tile: a generated, per-album tinted lattice with a note glyph instead of initials, so a library without embedded art still looks like a library and still colours the player.
  • Stage (Concept C3), a player-first layout, kept as an experiment rather than the default.

What remains unproven

  • No participant has used any of this. The validation plan lists nine tasks and six experiments with decision rules.
  • Nothing has run on Android. Frame rate, blur cost, TalkBack order, contrast over real artwork, timer timing and file writes are specified, not demonstrated.
  • Persian strings are drafts for native review.
  • Counts in the prototype (hidden songs, short files, unknown durations) are simulated around the observed 825-song baseline.
  • Lyrics content, covers and several tracks in the prototype are illustrative; every capture-derived title is listed in assets/kit.js with its source.

How the package was used

All 92 files were extracted and verified against the manifest hashes (92 of 92 matched). Every capture, Figma frame and prior-round image was read; the seven offline previews were rendered headless to read their text. No repository, device or Figma edit access was used or needed. The prototype and documents are self-contained HTML in this folder; exports/ holds PNG renders of the key screens.
